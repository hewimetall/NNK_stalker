# NNK Stalker — План полной порции настолки в WEB

**Заказчик хочет:** друзья играют **всю** настолку в браузере (не «лобби + надпись Игра стартовала»).  
**Источник правды:** `form.md.md`, `term.md.md`, уже существующие crates.  
**Стек не менять:** Rust · Axum · SQLite · JWT must-auth · web UI (Bevy — только если не тормозит поставку игрового стола).

---

## 0. Жёсткий менеджерский контракт (для всех агентов)

### Definition of Done (глобальный)
Партия считается **поставленной**, только если **живые 4–5 человек** могут:

1. Зарегистрироваться / войти  
2. Собрать лобби, стартовать  
3. На **игровом экране** (не лобби) выполнить цикл из `form.md.md`:  
   **D20 локация → ККК сектор → D20 гекс → D6 движение → фишка на гексе**  
4. Видеть карту/сектор/гекс/фишки всех игроков  
5. Пережить disconnect и **reconnect** в ту же партию  
6. Сыграть **хотя бы миссию 1** end-to-end (старт → цель миссии → запись в history)

Если любого пункта нет — **задача НЕ закрыта**. «Сервер отвечает 200» ≠ готово.

### Анти-саботаж (запрещено сдавать как done)
- ❌ Только лобби / «фаза playing» без UI хода  
- ❌ Клиентский RNG (кубики только server `nnk_rules`)  
- ❌ Монолит в `nnk_server` (правила только в `nnk_rules`)  
- ❌ «Потом сделаем карту» без playable hex/sector  
- ❌ PR без: тестов правил + smoke 4–5 игроков + скрин/видео игрового экрана  
- ❌ Ломающий HTTPS/HTTP деплой без рабочей публичной ссылки  

### Gate перед мержем каждой фазы
Агент **обязан** приложить:
1. Команды + вывод тестов  
2. URL стенда  
3. Чеклист DoD фазы (все галочки)  
4. Список того, что **осознанно не вошло** (если пусто — соврали)

Менеджер / следующий агент **имеет право отвергнуть** фазу без пунктов выше.

## 2. Целевая модель партии (обязательная)

### Фазы комнаты
`Lobby` → `Playing` → (опционально позже) `MissionComplete` / `CampaignComplete`

### Один ход игрока (инвариант из form.md — DO NOT SIMPLIFY AWAY)
Порядок **фиксирован** и проверяется тестами:

1. `RollD20Location` → `LocationId` (19–20 = reroll, не локация)  
2. `DrawCcc` → сектор 1..100 (десятки+единицы; `00`+`0` = 100)  
3. `RollD20Hex` → индекс гекса в секторе (нумерация L→R, T→B; **зафиксировать в ADR**)  
4. `RollD6Move` → ОД  
5. `MoveToken { to }` → путь ≤ ОД, только по гексам сектора/допускаемым правилам  

Нарушение порядка → `Err`, state не меняется.

### ГМ
- Старт лобби / старт миссии  
- Не подменяет кубики игрока  
- Видит тот же стол + лог `history`

### Must-auth
Без JWT нет join/action/ws. Исключения только `/health` + auth + static.

## 3. Фазы работ для агентов

> Каждая фаза = **отдельный PR** + gate. Не склеивать «всё сразу».

---

### P0 — Честность продукта (1 PR, блокер)

**Цель:** игрок не думает, что игра сломана, когда «Игра стартовала».

**Сделать:**
1. После `phase=playing` UI **прячет** кнопки лобби (create/join/ready/start)  
2. Показывает экран «Партия» (даже заглушку) с: код комнаты, список токенов, mission_id, history  
3. Reconnect seated player в `playing` **без** `game already started` (уже частично есть — закрыть e2e)  
4. HTTP playable URL в README/deploy (для сетей, где :443 режут LE)

**DoD P0:**
- [ ] Скрин: после старта виден **play panel**, не лобби  
- [ ] `stalker` reconnect в playing → 200 join + тот же roster  
- [ ] Smoke: 5 игроков → start → все видят play panel  

**Стоп-кран:** если сдали «добавили текст» без смены layout — reject.

---

### P1 — Протокол игрового стола (server + DTO)

**Цель:** клиент получает полное состояние для отрисовки и шлёт ходы.

**Сделать:**
1. Расширить `LobbyView` → `RoomView` (или добавить `PlayView`):  
   - tokens: name, hex `{q,r}`, move_points, location, ccc_sector, is_gm, is_active  
   - `active_user_id`, `mission_id`, `legal_actions[]` для текущего user  
   - `history` last N + `last_events`  
2. REST `POST /api/rooms/{code}/action` body = tagged action (`roll_d20_location`, …)  
3. WS пушит `lobby`/`room` после каждого успешного `step`  
4. Snapshot в SQLite переживает рестарт процесса (сейчас cold join хрупкий — **починить**)

**DoD P1:**
- [ ] Unit: порядок хода enforced  
- [ ] Integration: action REST меняет hex/location  
- [ ] После `systemctl restart nnk` комната восстанавливается **или** явный documented migrate (не «room not in memory» для активной партии)  
- [ ] OpenAPI/краткий `docs/API_PLAY.md` список action  

**Докапывание:** если `legal_actions` пустой в playing для игрока с ходом — reject.

---

### P2 — Правила 1:1 с form.md (nnk_rules TDD)

**Цель:** движок соответствует настолке, не «примерно».

**Сделать / дожать:**
1. Таблица D20→локация (уже есть) + тесты на 1..18 и 19/20 reroll  
2. ККК: две колоды, порядок tens→ones, 100  
3. Нумерация гекса в секторе 1..19 (или 1..N) — **ADR с ASCII-схемой**  
4. D6 move + `MoveToken` distance  
5. Чей ход: `active_user_id` ротация после завершения цикла 1–5  
6. Coverage gate: `scripts/coverage.sh` ≥ 93% на `nnk_rules`+`nnk_domain`  

**DoD P2:**
- [ ] Property/unit: одинаковый seed → одинаковые dice  
- [ ] Illegal action matrix (≥15 кейсов)  
- [ ] Документ `docs/TURN_PIPELINE.md` с примером хода  

**Докапывание:** «гекс пока randomly» без ADR нумерации — reject.

---

### P3 — Web игровой стол (главная поставка UX)

**Цель:** в браузере видно и кликабельно.

**Минимальный playable UI (без Bevy, если быстрее):**
1. Сетка сектора (19 гексов) + подпись локации/сектора  
2. Фишки игроков на гексах  
3. Панель действий = только `legal_actions` с сервера  
4. Лог бросков/истории  
5. Mobile + desktop (первый viewport не свалка карточек)  
6. Prefers HTTP-safe websockets (`ws`/`wss` от `location`)  

**Bevy WASM — только после** playable HTML стола (иначе снова «шелл без игры»).

**DoD P3:**
- [ ] Видео 30–60с: 2+ вкладки, полный цикл хода  
- [ ] Нельзя нажать illegal action (кнопка disabled или 4xx + UI)  
- [ ] Hard-refresh mid-game → тот же стол  

**Докапывание:** canvas без кликабельных ходов — reject.

---

### P4 — Миссия 1 (контент + гейт кампании)

**Цель:** не абстрактные кубики, а **миссия**.

**Сделать:**
1. `StartMission { mission_id: 1 }` задаёт цель/условия из дизайн-дока (если текста миссий мало — вынести в `content/missions/01.md` + JSON objectives)  
2. Win/fail condition проверяется engine  
3. UI показывает цель миссии  

**DoD P4:**
- [ ] Smoke: 4 игрока проходят миссию 1 до флага complete  
- [ ] History содержит mission_started / mission_completed  

---

### P5 — Миссии 2–10 + ГМ-инструменты

**Цель:** кампания.

**Сделать:**
1. Контент миссий 2–10 (JSON + короткие тексты)  
2. Прогресс кампании в `RoomState`  
3. ГМ: next mission, kick AFK (осторожно), force-skip хода с логом  
4. Сохранение между сессиями  

**DoD P5:**
- [ ] Можно пройти кампанию на стенде (хотя бы ускоренным GM-mode для теста)  
- [ ] 10 mission files существуют и валидируются тестом  

---

### P6 — Прод / устойчивость (параллельно с P3+)

**Сделать:**
1. Публичный URL: HTTP + HTTPS; fallback `:8443` если DPI режет 443  
2. DNS AAAA на реальный IPv6 **или** инструкция «force IPv4»  
3. `systemd` + nginx + cert renew  
4. `scripts/smoke-play.sh`: register×5 → lobby → start → full turn pipeline  
5. Reconnect / multi-tab  

**DoD P6:**
- [ ] С двух разных сетей (или curl -4/-6 матрица) задокументирован рабочий URL  
- [ ] Smoke-play зелёный в CI или на VPS

## 6. Метрики «агент накосячил»

Менеджер (или следующий агент) **реджектит**, если:
1. Нет доказательств smoke  
2. Coverage правил упал  
3. UI снова показывает лобби-кнопки в `playing`  
4. Кубик бросается на клиенте  
5. «Сделано» = только docs без кода  
6. Сломали auth/lobby регрессией

## 8. Явный критерий успеха для заказчика

> «Открыли ссылку → 4–5 друзей → сыграли миссию 1 на гексах с ККК/D20/D6 → можно рассказать, что произошло».

Всё, что меньше — **недоделка**, не «MVP настолки».
